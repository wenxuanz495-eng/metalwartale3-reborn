# 玄武（感应炮）家族 2.5 与 GitHub 对比报告

对比日期：2026-09-06
对比范围：2.5 原版 ↔ 3.4 原版 ↔ GitHub 仓库当前版本（三版），覆盖配置、资源与运行时代码。
证据等级：配置与代码差异为 A 级（文件直接取证）；资源结构差异为 B 级（FFDec XML 结构 + 位图/变形形状归一化哈希取证，未实机验证）。

## 一、家族定位

**玄武 = 感应炮家族（`arms index="6" id="induction"`）的 LV4 形态**。四形态：青龙(LV1) / 白虎(LV2) / 朱雀(LV3) / 玄武(LV4)，三版一一对应，无 3.4 式 ID 错位。

该家族为**双发结构**（`shootNum=2`），且带 `bulletLink` 子弹链接（详见第四节，本次最重要的发现）。

## 二、配置层对比（A 级）

三版完全一致的字段（逐字段核对）：

- `imgLabel`：induction_lv1 / lv2 / lv3 / lv4；`bulletImgLabel`：四形态共用 `arms/induction_lv1_bullet`
- `attackType=boom`、`bulletType=bullet`、`bulletSpeed=2`、`attackGap=0.1`、`recoilValue=2`
- `bulletNum`：1 / 2 / 2 / 2；`bulletTranslation`：3 / 4 / 5 / 6；`attackDelay=0.01`、`shootNum=2`
- `hurt`：33 / 42 / 55 / 71；`bulletLife=3`、`bulletWidth=7`；能量 24/20/24/24 + 0.025
- 链接定义 `induction_1`（感应炮直线）：`attackType=energy`、`bulletType=laser`、`penetrationB=1`、`bulletLife=0.001`、`bulletWidth=2`、`hurt=33/41/55/71` —— 三版一致

存在差异的字段：

| 字段 | 2.5 | 3.4 | GitHub | 定性 |

| `hitImgLabel`（主家族） | `sub/boom_hit_effect` | `bullet/purple_boom` | `bullet/purple_boom` | 原版 3.4 时期演进（与霰弹炮同型） |

| `price` | 10万/10万/50万/100万 | 同 2.5 | 1万/5万/10万/20万 | 离线版经济调整 |
| `mustItems` | 数字三元组（lv1 空） | 命名物品 | 数值大减三元组 | 离线版调整 |

## 三、资源层对比（arms_34 ↔ arms52 ↔ arms1100，B 级）

### 3.1 导出符号

三版同为 5 个导出：induction_lv1–lv4 + induction_lv1_bullet。
ID：2.5 = 436/430/424/418/409；3.4 = 755/749/743/737/728；GitHub = 1326/1320/1314/1308/1299。

### 3.2 本体时间轴：美术全部同源，但 GitHub 压缩了保持帧

本体结构：f1 本体+挂点 → f2 开火闪光(d3)+烟雾变形(d4，DefineMorphShape)+StartSound → 闪光消退/本体复位 → 尾焰(d2)→尾焰变形 → 结束。

美术逐项归一化哈希：**全部一致** —— 四形态本体形状、四形态开火闪光形状、烟雾变形形状（435==754==1325）、尾焰两帧形状（416/417 == 1306/1307）、开火音效（2.5 soundId=352 == 3.4 =764 == GH =1240，soundData 同哈希）、各形态尾焰缩放（lv1/lv2 纵向 0.5、lv3 纵向 0.75、lv4 无）、挂点坐标（lv1 base(204,320)/shoot(1294,380) 等）。

**唯一结构差异——帧数压缩**：

| 形态 | 2.5 帧数 | 3.4 帧数 | GitHub 帧数 |
|---|---:|---:|---:|
| lv1 | 7 | 7 | **5** |
| lv2–lv4 | 6 | 6 | **5** |

GitHub 删掉的是：①闪光帧之后"烟雾变形单独保持 1 帧"的帧（四形态都有）；②lv1 结尾的 1 个空保持帧。**压缩发生在 3.4 → 11.3 之间**（3.4 与 2.5 帧数一致）。影响：烟雾消散过程在 GitHub 少约 1–2 帧（33–66ms），尾焰出现提早 1 帧；攻击周期本身 0.1s×2 发 + 间隔，动画整体仍在一个周期内播完，差异属细微节奏差。

### 3.3 子弹：完全一致

两帧 Sprite（本帧形状 + 第 2 帧换形），主形状归一化一致，位图 71×69 zlib SHA 相同（`6ac801bb...`）。感应炮弹是绿色球体，三版同源。

### 3.4 挂点标记小图形：颜色不同但实机不可见

basePoint/shootPoint 引用的是全武器共用的标记圆点（19×19px，2.5 半透明黑色 alpha128 ↔ 11.3 不透明白色 alpha255）。运行时 `SWFLoaderManager.getSingleMovieclip` 读取坐标后执行 `pmc.visible = false` 把标记**隐藏**，因此颜色差异不影响实机画面；有效信息只有坐标（两版一致）。此前霰弹炮结构对比中该点也是差异来源之一，特此澄清。

## 四、关键发现：bulletLink 首发激光在 GitHub 失效（A 级）

- 机制（`OneArmsDefine.inData_byXML` + `ArmsAttack.attackPan`，两版代码一致）：`bulletLink.index = int(xml.bulletLink.@index)`；发射时第 `index` 发改用链接定义（`d2 = bulletLink.getDefine()`，`laser` 类型 → `LaserBody`）。
- 2.5/3.4 配置带 `index="1"`：**每个攻击周期的第 1 发是"感应炮直线"——激光穿透束**（life=0.001 瞬时、penetrationB=1、自带受击特效），第 2 发才是普通 boom 弹。
- GitHub 配置丢了 `index` 属性 → `int(空XMLList) = 0` → `shootNum==0` 永不成立 → **替换永不触发，两发全是 boom 弹**，激光穿透束（含其 hurt 33/41/55/71 与 yellow_energy 受击特效）整体失效。
- 该属性在 3.4 中仍在，**丢失发生在 3.4 → 11.3**，属原版演进（或 11.3 的失误），不是离线版改动。
- 这是本家族实机观感差异最大的点：2.5 的感应炮是"一线穿透激光 + 一发爆能弹"，GitHub 是"两发爆能弹"。

## 五、对"2.5 回迁"的可选项（按影响排序）

1. **恢复首发激光（推荐优先）**：把 4 行 `<bulletLink>` 恢复为 `<bulletLink index="1">arms/induction_1_lvX</bulletLink>`。纯配置修改；GH 代码路径（`LaserBody`、laser 分支）完整存在，但需实机验证激光渲染资源链（LaserBody 的贴图来源）在当前仓库可用。
2. **本体烟雾节奏**：如需 2.5 的 7/6/6/6 帧节奏，需从 2.5（或 3.4，内容相同）导入时间轴帧序——美术全部同源，仅需在时间轴插回保持帧，属中等复杂度时间轴编辑；收益为烟雾多显示约 1–2 帧。
3. **受击特效**：主家族 `purple_boom`→`boom_hit_effect`、激光 `yellow_energy`→`energy_hit_effect`，均纯配置；但 3.4 已自行切换（先例：霰弹炮/火神炮保留现状）。
4. commonLevel/price/mustItems 为离线版刻意调整，不在特效范畴。

## 七、补充核查（2026-09-06 追问：11.3 是否仍在发射激光）

针对"11.3（GitHub 基底）依旧是激光攻击"的疑问，追加核查结论：

1. **无任何文件或代码补充 bulletLink 机制**。全仓库 `bulletLink` 只出现在 `OneArmsDefine`（解析）与 `ArmsAttack.attackPan`（发射分支）；无 induction 专属代码（仅敌方英雄 AI 武器列表引用 `induction_lv4`）。
2. **11.3 原版本来就没有 index**。对初始提交 ba10543（11.3 数据原样导入基线）取证：内嵌配置中 4 行 `<bulletLink>` 均已无 `index` 属性；基线版 `OneArmsDefine`/`ArmsAttack` 的解析与发射代码与当前逐字一致（`index = int(@index)` → 缺属性 = 0 → `shootNum==0` 永不成立）。即激光首发在 11.3 原版已失效，GitHub 忠实继承，非离线版弄丢。
3. **"11.3 依旧是激光攻击"的观感来源 = 本体动画里的光束条（纯视觉）**。本体时间轴第 4～6 帧放置的 d2 图形（2.5 shape 416/417 ↔ GH 1306/1307，归一化逐字节一致）是一条 **703×4px 绿→黄→红渐变长光束**，发射时横向展开——这就是玩家看到的"激光"。2.5/3.4/11.3/GitHub 该视觉完全一致，所以 11.3 看起来依旧在"激光攻击"。
4. **2.5 的 bulletLink 激光不是纯视觉，是真实伤害组件**：`bulletType=laser` + `penetrationB=1` + `bulletLife=0.001`（瞬时穿透，`LaserBody` 定角定点渲染），每周期首发造成 33/41/55/71 点穿透伤害并触发 `energy_hit_effect`（2.5）/`yellow_energy`（3.4+）受击特效。11.3 起该伤害成分消失，感应炮实际输出 = 两发 boom 弹（33/42/55/71 ×2）。
5. 面板 DPS 公式（`getDps_byHurt` 的 bulletLink 分支）两版一致且只看 bulletLink 是否存在（不看 index），故面板数值未暴露此差异。

结论：**画面上的"激光"从未丢失（动画光条，各版一致）；丢失的是 2.5 首发的真实穿透激光伤害**。是否恢复该伤害成分（4 行配置加回 `index="1"`）属玩法决策，需实机验证 `LaserBody` 渲染链在当前仓库的可用性。

## 八、补充核查二（2026-09-06：追踪弹、闪烁频率、受击/爆炸特效专项）

> 术语约定（用户确认）：**"GitHub" 与 "11.3" 视为同一版本**，后文统一称 GitHub。

### 8.1 爆能弹是否追踪（2026-09-06 二次修正：初判有误，以本节为准）

> **勘误**：本节初版误判"三版均无 followB 字段、弹不追踪"，原因是字段抽样打印不全。经用户实测质疑后重新逐字段核查，修正如下。

- 2.5 / 3.4 / GitHub 三版感应炮配置**全部带完整追踪字段，且逐字段一致**：

```text
followB = 3          // 转向倍率（startFollow 生效时的vra系数）
followDelay = 1000   // 命中 >=1000 分支：低速自动瞄准
bulletMaxV = 30      // 加速上限
bulletMaxVa = 0
specialProperty = 跟踪
bulletVra = -1000
```

- 运行链路（两版代码逐字一致）：`followB=3 > 0` → `BodyGroupRefresh` 每帧为无目标弹分配目标（我方弹 `getHurt_RandomEnemy`，敌方弹锁定英雄）→ `followTarget()` 中 `followDelay=1000 >= 1000` 且弹速 `v0=2 < 5` → **每帧 `a0=4` 加速并把朝向立即转向目标**，同时 `startFollow` 以 `followVra=3` 持续追踪，速度上限 `bulletMaxV=30`。
- **这正对应实测现象"怪物出现和不出现时弹道速度不一样"：无目标时恒速 2 缓慢直飞；有目标时立即转向并以 a0=4 持续加速（最高 30）扑向目标。**
- **结论：追踪行为三版完全一致，GitHub 无任何缺失，无需修改。** GitHub 新增的只是其他武器的特殊弹种分支（FollowMaxV 等），不影响感应炮。

### 8.2 灯光/闪光频率（攻击周期逐帧核算）

攻击周期本身两版一致：`attackGap=0.1` 不变，双发间隔、周期节奏（约 8 帧 @30fps）相同，即**闪烁的频率（每秒次数）没有变化**。变化的是每次周期内各元素的**可见时长**（本体动画被 11.3 压缩 1–2 帧所致）：

| 元素 | 2.5（lv1 7帧 / lv2-4 6帧） | GitHub（全 5 帧） | 差异 |
|---|---|---|---|
| 枪口闪光 | 2 帧（67ms） | **1 帧（33ms）** | 闪光时长减半 |
| 烟雾变形（d4） | 3 帧 | 2 帧 | 消散更快 |
| 长光束条（d2，即"激光"视觉） | 第 5 帧出现 | **第 4 帧出现** | 提早 1 帧 |
| 攻击循环频率 | ≈3.75 周期/秒 | ≈3.75 周期/秒 | 无差异 |

## 九、补充核查三（2026-09-06：激光本体视觉与光束美术条）

### 9.1 激光束的可见机制澄清（修正此前表述）

- 游戏内激光确实**有独立的光束美术图**：`MaskArmsImage`（仅副武器图像 `SubImage` 使用）管理的武器动画内预置 1000px 光束条，代码按"炮口→命中点距离"设置遮罩宽度（`BodyGroupHit` 中 `arms.length = imgLen/1000`，仅 `penetrationB == 0` 分支）。用户截图的红黄渐变全屏光束即此机制（战殇/炽天使/敌方激光台）。
- **感应炮的激光（penetrationB=1）不走该机制**：induction_1 无 bulletImgLabel（两版一致）→ `LaserBody(false)` 无弹体图；主武器图像为普通 `ArmsImage` 非 MaskArmsImage；其可见画面 = 本体动画光束条 + 命中点受击特效（旋转对齐弹道）。两版机制代码逐字一致。

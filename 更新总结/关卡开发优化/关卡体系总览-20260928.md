## 一、总架构：数据驱动为主，脚本类极少

全游戏 **246 个关卡定义**（另有一个 `1-1-999` 空壳模板），几乎全部由三张嵌入表驱动：

| 表 | 语义 | 规模 |
|---|---|---|
| xmlClass11 | 关卡出兵表（关卡主定义） | 246 关 |
| xmlClass8 | 敌人属性表 | 130 条 |
| xmlClass9 | 敌方武器表 | （敌人开火配置） |

手写脚本关只有 **24 个类**，且经查证大部分是**无实例化路径的死代码**（见第七节）——真正活着的分发只有六个家族类。

## 二、关卡家族调度表（LevelGroup 构造循环，按 id 首段分发）

```text
id 首段     家族类（getDefinitionByName）          归属/说明
1-1~1-3  → Levels（1-3 例外 → GhostLevel）      packId="p1"（自由之心）；threeID<999 才入包
1-4      → Levels                                packId="p2"（月球危机）
2-x-x    → extra.ExtraLevel                      精英副本（45 关）
3-x-x    → extra.WeekExtraLevel                  每周副本（12 关）
4-x-x    → Levels                                特殊副本（11 关）
5-x-x    → ArenaLevel                            竞技场（1 关；全游戏唯一 type="boss" 代码赋值处）
6-x-x    → ⚠️ 无分支！沿用上一轮循环的 class0       公会战占位（5 关全空名）
```

- 表内有 `specialClass` 属性**预留覆盖通道**（`className0 != ""` 时覆盖家族类），但**全表 0 处使用**（99 处出现均为注释文档）。
- ⚠️ `6-1-1~6-1-5` 五关：无名字、无场景、无分发分支——依赖循环变量残留 class0，属脆弱写法，定性为公会战占位/死数据（待办）。
- `1-1-999`：空名空场景模板关，被 `threeID<999` 条件排除在 p1 之外；`chosenLevel` 中 `index0>=999` 时会指向它。

## 四、编号映射机制（本目录的核心口径）

**内部 → 扁平序号**（`LevelGroup.chosenLevel`，state="normal"）：

```as3
if(index0 < normal_num || index0 >= 999)   id0 = "1-1-" + index0;        // 0..30 → 1-1-0..30
else if(index0 < normal_num + knowing_num) id0 = "1-2-" + (index0-30);   // 31..42
else if(index0 < 100)                      id0 = "1-3-" + (index0-42);   // 43..69
else                                       id0 = "1-4-" + index0 % 100;  // 100..200
```

- **扁平序号 70~99 是死槽位**（映射到不存在的 1-3-28+，getLevel_byID 落空）——纯为"月球危机从 100 起"的整十边界凑数。
- **显示标签**（`LevelButton.setText`）：序号 0＝"序章"，其余＝"第 N 关"。
- **战役页"第十章 N"**：月球危机整包固定显示"第十章"，N＝内部 x+1（`1-4-1 突击部队`＝第十章 2，截图实核至 N=18）。⚠️ "第十章"三个字的**生成代码不在 gamefile UI 内**（全库 grep 无"章"字标签拼接），疑在 shell/加载器 swf——待定位（优化机会 #1）。
- 玩家口述"月球危机 10-1"＝显示第十章 1＝内部 `1-4-0 敌军来袭`。
- `LevelsDefine.getNowLevelIndex()`：`(章-1)*4+index` 的旧全局序号（遗留逻辑，疑存档兼容用，待考）。

## 六、关卡 XML 字段参考（LevelsDefine.inData_byXML）

`id`（三段式）、`name`、`father`、`scene`→sceneID、`loopMusic`（缺省 `enemy_coming2`）、`bornPoint`/`exitPoint`、`enemyLife_ra/enemyHurt_ra/enemyExp_ra/enemyCoin_ra`（难度外关卡级数值倍率）、`<unit>`（属性 `number/type/life/firstDialogue/dialogue`，type∈`boss|champion|super`，空＝普通）、`storyOrder`/`eventOrder`（剧情/事件指令）、`limitTime`＋`timeOverOrder`(fail/win)＋`timingText/timeOverText`（限时关）。

**Boss 双通道**：①`level@boss` 属性（**仅 16 关，全在 p1**：1-1 十四关＋1-2-3 猎隼战机＋1-3-7 "未知"；月球危机 0 关）；②`unit type="boss"`（月球危机唯一手法）。boss 血条触发点是代码判 `b0.type == "boss"`（`Level_2_13/Level_6/Level_2_11` 等），与 `level@boss` 属性无关。**统计口径必须分清**（详见 README 已确立口径节）。

## 七、脚本关接线（2026-09-29 勘误重写）

**机制**：家族类兜底（第二节分发表）→ 关卡 `<specialClass>` 子元素覆盖（`getDefinitionByName`）。**全部 26 个脚本类都在使用，无死代码**（初版"死代码三证据"系子元素漏采所致，作废）：

- **战役脚本关 37 个**：序章=Level_0；突击者队长=Level_3；城市杀手=Level_6；先知现身=Level_2_4；千里追击=Level_2_5；先知章防线四连（建立/稳固阵地、北部/南部防线）=Level_2_9~12；幽灵章五关=Level_3_1/3_3/3_13/3_15/3_16（3_1 管三关）；**月球危机 22 个攻城/守点关=Level_2_5**（倒计时基类）。
- **副本**：1-1-999＝Vip 专属地图→`VipExtraLevel`（**3.0.1 VIP 矛盾就此解开**：VIP 副本可达且活着）；2-1 精英＋6-1 公会战→`SpecialExtraLevel_11`；4-1 特殊副本→`SpecialExtraLevel_1..10`。
- 唯一孤儿：`ExtraLevel`（含回血球＋紫芯片机制）——2-1 全部被 specialClass 覆盖后无实例（影响见《副本关代码全解》）。

## 八、场景体系

`scene` 字段 → `LevelsDefine.sceneID` → `Game.oneScene` 校验/加载 → `swf\scene_*.swf`（alien/base/city/moon/mothership/ruins 及 2/3 变体）。注意：

- **两代命名并存**：1-1/1-2 用中文标签（基地/大都会/废墟/月面N），1-3/1-4 用英文键（base_ghost/alien/mothership_ghost）。
- **脏数据实录**：`城市=`（1-2）、`废墟-——————特殊关卡`/`月面-——————特殊关卡`（1-1）、`月亮2` vs `月面1`（疑似同一场景两种写法）、空场景若干（1-3 三关、1-4 一关、副本全系）。
- 场景加载类名历史拼写：`OneSence.as`（非 OneScene），检索时注意。

## 九、难度体系

`DifficultBox`：普通/噩梦/地狱/炼狱 = diff 0~3；成绩存档键 `packName_diff_level`（`NewLevelData.setScore`）。难度是**同一份关卡数据的倍率层**，不产生独立关卡 id。

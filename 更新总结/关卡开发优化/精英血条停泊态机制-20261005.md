# 精英血条「停泊态」机制 —— 血条出现 ≠ 怪物在场（2026-10-05）

> 缘起：拦截机1号登场噪声考（见 `..\怪物总结\月球怪物合集\67，拦截机1号\`）中，「进关时场外已有满血精英血条」被多轮误读为"精英已注册/已刷新/已隐身"。本机制考证由用户跨关实验＋代码逐行核对双重实锤，**纠正一条长期污染推断的基线**。此机制影响所有"看到血条→推断有怪"的观测与调试判断，故立专档于关卡开发优化目录。

## 一、结论速览（红线）

1. **带名字的精英血条是屏幕 UI 控件，不是怪物的伴生组件。它永不卸载，只会在舞台顶边外"停泊"。**
2. **血条出现 / 血条在场外 / 血条满血静止——都不构成任何"怪物已刷新 / 已注册 / 在场"的证据。**
3. **零波次（进关→第一个 area 触发点之间）精英怪绝不刷新**：出兵唯一链＝玩家车压到 `area` 点 → `Levels.hitArea`（`gameAll\level\Levels.as:296`）→ `openEventOrderDefineGroup`（`Levels.as:216`）→ `EventOrderDefine.doOrder`（`gameAll\order\EventOrderDefine.as:270`）逐个出兵。代码中不存在进关预刷路径。
4. **禁止再把血条当机制推断的证据**。需要判断"精英是否在场"时，看敌人数组/浮动等级条，不要看 boss 血条。

## 二、机制全解（代码证据链）

**血条本体**＝`UI\gaming\GamingUI.as:64` 的 `boss_bar:LifeBar2`（`UI\gaming\LifeBar2.as`）。屏幕空间 UI，包含：`nameTxt` 精英名、`skillTxt` 词条技能名（`ai.skill.getCn()`，即"能量爆发/坚毅"这类词条）、`txt` 血量数字、`cover.scaleX` 血量比例条。

**显隐机制**（`GamingUI.as:426-490`）：

- `showBossBar()`（:426）：条从 **y=-53.5**（舞台顶边外）补间滑入到 y=23.5（0.3 秒 Back.easeOut）——玩家看到的"血条弹入关卡"就是这段补间。
- `hideBossBar()`（:440）：滑回 y=-53.5 停泊。**条永远不从显示列表移除**——缩小 Flash 画布（播放器右键缩小）就能看到它停在舞台上方场外。
- 数值刷新（:350）：**仅当 `bossBarTarget != null` 时**每帧 `inData(now, max)`；target 为空时没有任何代码碰它——内容定格，这就是"无法变化"的原因。
- 唯一的显示触发＝`bossBarTarget` setter（:452）赋非空值。全库 `showBossBar` 调用者仅 setter 一处。

**target 的生命周期**：

- 挂上：`EventGroup.bodyAdd` 中 `type == boss/super/champion` 的怪**刷出瞬间**（`gameAll\EventGroup.as:1481`）；或非 soldier 型怪**被击中**时（:1103）。
- 置空①精英死亡：`EventGroup.as:1672-1675` → `hideBossBar` 停泊，**条面定格为归零态**。
- 置空②关卡结束：`UIGroup.gameOverFlesh`（`UI\UIGroup.as:525-526`）→ 停泊，**条面定格为退出时的状态**。
- 注意 setter 有 `if(_bossBarTarget != b0)` 防抖：已是 null 再赋 null 是 no-op。

**三态观测对照表**（用户一手观测 ↔ 机制状态）：

| 观测 | 时机 | 机制状态 |
|---|---|---|
| 场外满血静止条、显示精英名 | 第0波→第1波（进关后） | **上一局退出时精英还活着的遗留内容**（月球关反复重打时精英几乎必然存活到玩家退场）；【推测】全新会话首次进关应显示 UI swf 出厂默认态 |
| 场外归零残留条 | 第1波→第2波（精英死后） | 精英死亡瞬间血量归零后停泊，等内容被下一只精英覆盖 |
| 血条从上方弹入、随精英可变 | 精英刷出时 | `bodyAdd` 挂 target → 滑入补间 → 数值恢复每帧刷新 |

**铁证实验（用户执行，2026-10-05）**：先打月球关、再进地球关——地球关卡外停泊条上显示**"拦截机1号"**（月球怪，地球关绝不可能刷）。停泊态定案。

## 三、与另一套条的区分（勿混淆）

**怪头顶浮动等级条**＝`UI\gaming\EnemyLifeBar`（`Game.gameSprite.textL` 世界层，含等级数字、无名字）：

- 仅在 `BodyGroup.addLifeBar`（`bodyGroup\BodyGroup.as:592`）被调时创建，常规调用点＝`bodyAdd` 内（`EventGroup.as:1520`，每怪各一条）；`Satellite_AI.as:23` 与个别特殊关另有直调。
- `BodyGroupRefresh.refreshLifeBarTimer`（`bodyGroup\BodyGroupRefresh.as:189-209`）每帧驱动：死亡（`die != 0`，`Normal_FlyBody` 的 die 为计算属性——`toDie` 置 `_die=1` 即刻生效）后**下一帧即从 textL 移除**。
- 关卡关闭时 `Game.as:1043 → BG.clearAllEnemy() → delAllLifeBar()`（`BodyGroup.as:2058`）全清。
- 因此**浮动条不残留**；尸体飞出舞台时浮动条最多跟随约一帧。长期残留的只可能是 boss 停泊条。

## 四、被本机制作废/需修正的旧推断

1. "血条出现＝精英已注册/已刷新"（含交接材料"血条=注册非在场"的表述）——**作废**。
2. "进关时场外有血条＝精英已整体刷新只是隐身/在场外"——**作废**（停泊遗留）。
3. "4 只 champion 依序覆写血条＝4 只依序在场"——覆写顺序本身成立（每只 bodyAdd 挂 target 时覆盖内容），但**战斗进行中**之外的血条观测不可作为在场证据。
4. 噪声考中基于血条时间线的一切中间结论——已按新基线重推（终局结论见 34 号档案待补节）。

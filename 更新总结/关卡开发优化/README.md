# 关卡开发优化 · 工作记录区

> 定位（2026-09-28 用户立项）：关卡体系与开发口径的**开发侧优化**工作记录区——只做不影响游戏实际体验的优化（口径文档、编号映射、数据表索引、工具沉淀）；**不改 decompiled 源码结构、不动游戏数据与构建产物**。
> 立项背景：内部关卡编号与游戏内显示编号不一致、嵌入表匿名编号（xmlClassN）无语义索引、关卡表 boss 标记混装设计 Boss 与复用型关卡 boss——这些口径此前全靠踩坑获得，本目录负责把口径固化下来，服务后续开发（含 TACTICAL_MODE 战斗更新/独立副本）。

## 路线裁定（2026-09-29，用户论证成立）

- **存量重构（重命名旧类/重写旧系统）为支配劣势选项，从选项表划掉，非"暂缓"**：其代码层工作量（改＋修 bug＋测试回归）与移植新引擎的代码层工作量同量级（两边的"修 bug＋测试"部分几乎相同），但收益只有可读性，远小于换平台收益——投入相近、收益差量级，被"不动"与"重写"两端支配。
- **若未来真需要大改：直接评估新引擎路线（Godot 类），跳过重构中间站。** 触发条件唯一：项目目标从"保存原版"转向"重制再创作"（换引擎≠本项目的优化，是另一个项目——FFDec 链/基线哈希构建/素材回迁机器是"保存"使命的承重结构）。工具链变化（如原生链复活）只降低日常改码成本，**不**构成本裁定的重评理由。
- **未来移植的可行性备忘**（届时不是空话）：存档格式已逆向完成（sasave＋五件套，见 存档工具/档案）；素材库有 FFDec 全量导出（2.5/3.4/4.0）；最大工作量＝时间轴动画重建＋内容对齐；HTML5 导出可顺带解决 Flash Player 依赖。
- 本目录的存在形态＝不动存量：口径文档＋翻译工具＋新代码新命名（TACTICAL_MODE 等新内容自带秩序）。

## 工作记录约定

- 每项工作一篇 `主题-YYYYMMDD.md`，遵循 `..\README.md` 归档规则（目标 / 实际修改 / 验证 / 待办 四段）。
- 比对产生的数据表（CSV）与脚本随记录同夹存放；脚本转正时移入 `scripts\` 并在此登记。
- **查关工具（2026-09-29 转正）**：仓库根 `查询关卡.bat` ＝ `scripts\level_lookup.py`——支持 内部 id / `第十章 N` / `10-N` / `序章`·`第N关` / 名称模糊 / 分类名（精英副本·玩家副本·特殊副本·公会战…）/ 脚本类名，实时解析关卡表（无缓存），无参数时打印口径速览。
- **红线**：本目录工作不得改变构建产物哈希（不碰 `swf\` 源资源、不登记 `swf-script-patches.txt` 即不应有任何 game.swf 变化）；确需触碰游戏数据时另行走正式改动流程并在记录中声明。

# 更新总结 · 总索引

> 定位：本目录归档游戏**所有更新的任务总结**——每次功能、回迁、修复做完后，把"改了什么、怎么验证的、还剩什么"写成 MD 存放在这里，让后续维护者有架构可循。
> 分工边界：工程规则与架构文档在 `docs\`；玩家可见的更新说明在发行包 `公告.txt`；过程性工作区（中间产物、测试包）在 `tmp-soya-family-test\`，**不归档入本目录**，只把最终版总结和关键脚本/证据图收进来。

## 目录架构

```text
更新总结/
├── README.md              本总索引
├── 版本更新总结/           按版本归档的系统级更新（一个版本一个子文件夹）
│   └── 2.4.1更新/
├── 功能性更新总结/         功能性新功能（非武器家族、非版本批量，如隐藏称号）
├── 武器特效总结/           武器家族 2.5/3.4 特效回迁专项（内有独立的家族索引 README）
│   ├── README.md          家族分类索引（先读）
│   ├── 通用/              跨家族方法论、代码机制、数值公式
│   ├── <×××家族>/         一个武器家族一个文件夹（含脚本、对比图、备份文件夹）
│   └── 相关bug修复/        武器相关的 bug 修复记录
└── 未完成重点任务/         已立项未完成的任务；完成后移出到上面三类，本目录不保留副本
```

## 新更新怎么归档（规则）

1. **选位置**：
   - 围绕某个武器家族的改动（特效回迁、家族数值、家族 bug）→ `武器特效总结\<家族名>\`
   - 功能性新功能（新增玩法、界面功能等）→ `功能性更新总结\`
   - 跨武器的系统级改动（界面、存档、商城、公会、启动器、构建流程）→ `版本更新总结\<版本号>更新\`，没有对应文件夹就按版本号新建
   - 已规划未做完 → `未完成重点任务\`；完成后移出到对应分类，不在两处重复存放
2. **命名**：`主题-YYYYMMDD.md`（日期用完成日）；对比图 `主题对比图-YYYYMMDD.png`；回迁/合并脚本用可读英文名（如 `plasma_restore_merge.py`）
3. **总结 MD 必备四段**：目标、实际修改（改了哪些文件+代码/资源锚点）、构建与验证（哈希、回读、像素比对等证据）、待实机确认项
4. **移除资源必须留备份**：在对应家族/分类文件夹下建 `备份-移除的孤儿资源-YYYYMMDD\`，存放移除前完整副本、渲染存档和 README 说明（范例见 `武器特效总结\等离子炮家族\备份-移除的孤儿资源-20260907\`）；长期确认无用途后可整体删除
5. **更新索引**：归档后同步更新所在分类的 README（`武器特效总结\README.md` 的家族清单和"本轮变更清单"；`版本更新总结` 暂以文件夹名为索引）
6. **提交**：总结归档与代码修改分开或合并提交均可，但必须在同一次推送内，保证"代码到了 GitHub、总结也到了"
